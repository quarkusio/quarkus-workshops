// Reusable instructions for creating a Quarkus Gradle project without the
// Quarkus CLI (used when the use-no-quarkus-cli attribute is set).
// The including file must set the {app-name} attribute first, e.g. `:app-name: rest-villains`.
[NOTE]
====
It is *much* easier to create a Quarkus project with the Quarkus CLI (`quarkus create app ...`) or from https://code.quarkus.io.
These instructions assume the Quarkus CLI is not available in your environment (for example, a locked-down environment where it cannot be installed), so we use Gradle's `init` task with the Quarkus build init spec instead.
They do assume that Gradle is installed locally, so the `gradle` command is available.
====

Under the `quarkus-workshop-super-heroes/super-heroes` directory, scaffold the module with the Quarkus build init spec:

. Create the module directory and run `gradle init` from inside it:
+
[source,shell,subs="attributes+"]
----
mkdir {app-name} && cd {app-name}
gradle init -Dorg.gradle.buildinit.specs=io.quarkus.init:{quarkus-version} --type quarkus-app
----
+
This generates the Gradle build files, the Gradle wrapper (the `./gradlew` commands used throughout the rest of this workshop work), and a basic Quarkus project layout.
+
[NOTE]
====
Gradle build init specs are still incubating, and `gradle init` does not yet let you pass the generator's parameters (group, artifact, extensions, ...).
The project is therefore generated with the default values, and we adjust it in the next steps.
====

. The project is generated with the default name (`code-with-quarkus`) and group (`org.acme`), so adjust them:
+
* in `settings.gradle.kts`, set `rootProject.name="{app-name}"`,
* in `build.gradle.kts`, set `group = "io.quarkus.workshop.superheroes"`.

. In `build.gradle.kts`, the generated project depends on `quarkus-arc` and `quarkus-rest`.
Add one `implementation("io.quarkus:quarkus-<extension>")` line for each of the extensions listed for this service (the extensions are described just below), for example:
+
[source,kotlin]
----
implementation("io.quarkus:quarkus-rest-jackson")
----

NOTE: The generated `src/main/docker` directory already contains the Gradle-ready `Dockerfile` files (they reference Gradle's `build/` output directory), which the _Building Containers_ section needs.

You now have the same project the Quarkus CLI would have generated, including the sample resource class, tests and configuration.
